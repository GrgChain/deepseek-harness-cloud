# ADR-03 独立持久卷生命周期

- 版本：V0.1
- 范围：单组织 Docker 初始版本
- 状态：已选择设计，待实现验证
- 负责人职责：后端/集成开发与安全验证
- 关联需求：REQ-04、REQ-08、REQ-09、REQ-10、REQ-11

## 1 合理性评估

合理，属于数据保护必需能力。必须同时保证停止保留和 Workspace 删除保留。

## 2 背景与约束

工作文件及已验证配置/会话需要跨计算重建保存。仅把卷放入工作空间模板，并不能表达平台要求的独立软删除与保留策略。

## 3 备选方案

| 方案 | 收益 | 代价与结论 |
| --- | --- | --- |
| 受信存储模块独立管理，模板引用既有卷 | 计算和数据销毁权限分离 | 需登记/对账，作为当前方案 |
| 与 Workspace 共同管理生命周期 | 模板简单 | 删除可能连带数据，不满足软删除保留 |
| 只依赖备份 | 有故障恢复副本 | 不能替代日常原卷复用，不单独采用 |

## 4 当前选择

首版采用独立固定容量文件系统资产，Docker卷绑定已挂载资产，准备/启动排他与entrypoint二次标记检查，具体见 [运行适配](../backend.md#124-存储与模板契约)。StorageAsset 登记稳定卷名、Owner、实例、容量和初始化标记。受信存储模块创建/核验卷，Workspace Terraform 模板仅挂载已授权的既有卷，卷不属于 Workspace 的销毁资源集合。独立管理可为同一工程内模块，不要求单独存储微服务。

不存在的原卷必须报错。须验证 Docker/Provider 的实际挂载行为，防止挂载不存在的卷名时隐式补建空卷；校验与挂载之间的竞争也要处理。原卷名/归属不可由成员覆盖。

停止保留原卷；软删除仅撤销访问及计算，数据进入保留状态。永久回收仅受控运维执行；恢复写入同Owner的另一个已停止实例资产，保留原实例/原卷及计账，不改变每实例一个原资产的约束，具体见[恢复规则](../deployment.md#5-备份恢复与保留)。

## 5 代价与边界

卷登记、文件系统限额、保留与独立备份都需实现。命名卷容量字段不等于硬限额；卷初始化和备份一致性必须按 DSH 目录验证。在途进程不承诺恢复。

## 6 验证与放行

TC-04、TC-06、TC-13、TC-15、TC-24、TC-29。检查 Terraform 销毁计划和实际删除；验证原卷、文件哈希、缺卷及挂载竞争、保留计量与独立备份恢复。

用例定义见 [测试验收](../testing.md)，结果当前未执行。验证失败时暂停对应能力放行，重新评审方案。

## 7 技术依据

Docker 官方 [Volumes](https://docs.docker.com/engine/storage/volumes/) 说明卷的独立生命周期及创建行为；Coder [Resource persistence](https://coder.com/docs/admin/templates/extending-templates/resource-persistence) 说明模板持久化设计。实际模板仍需验证。
