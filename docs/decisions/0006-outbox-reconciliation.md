# ADR-06 操作记录、Outbox 与对账

- 版本：V0.1
- 范围：单组织 Docker 初始版本
- 状态：已实现并验证租约/原子事务和真实生命周期/构建响应丢失恢复；完整故障矩阵待验收
- 负责人职责：后端/集成开发与安全验证
- 关联需求：REQ-04、REQ-05、REQ-08、REQ-09、REQ-10、REQ-12

## 1 合理性评估

合理，属于异步可靠性必需能力。数据库租约只能约束回写，外部副作用必须另外防重。

## 2 背景与约束

实例/操作/Outbox 接受事务与 Workspace/Build 登记分阶段提交；Terraform、卷准备和配置注入位于外部执行边界。提交结果未知、重复任务和 Worker 崩溃都可能发生在动作成功之后。

## 3 备选方案

| 方案 | 收益 | 代价与结论 |
| --- | --- | --- |
| PostgreSQL 操作/Outbox + Worker 对账 | 无额外队列，业务和任务同事务 | 需实现领取与幂等，作为当前方案 |
| 请求内同步执行全部动作 | 代码路径短 | 不能可靠恢复超时/中断，不采用 |
| 独立消息队列/工作流集群 | 提供调度能力 | 仍需外部幂等，首版不引入 |

## 4 当前选择

单事务保存实例、幂等记录、Operation、Outbox、资源预留与审计，提交后返回 202。锁序/SQL约束见 [数据设计](../data-model.md)，租约/超时/幂等数值见 [配置基线](../deployment.md#8-配置与业务规则基线)。Worker 有界领取、续租，条件更新同时校验租约 token 与实例/操作版本。每实例只有一个 ACCEPTED/RUNNING/UNCERTAIN 操作。

首次接受时持久化稳定的外部创建标识，Workspace 名称依据不可变实例 ID 派生，显示名称另存。重放使用同一 Owner、名称、模板版本与配置快照。调用前后查询已登记资源和 Build；不能确认资源归属时不得接管。

超时进入 UNCERTAIN，保留额度并对账。数据库 fencing 不能撤回旧执行器已执行的 Terraform 效果；Workspace 唯一约束、单活动 Build、数据库/主机锁及原 state 共同约束重试，须处理迟到成功和接管竞态。无法证明安全时继续保留未知状态，禁止换名称重建。

启停/删除/配置动作也要核实同一资源及进行中的 Build。确认释放资源后才释放配额；必要就绪检查失败时记录 FAILED 和已存在计算/卷。

Redis 用于短期缓存与限流；Operation/Outbox、租约和资源预留仍在 PostgreSQL。缓存丢失不丢任务，Redis 锁不代替数据库约束，分工见 [ADR-08](0008-backend-stack.md)。

## 5 代价与边界

交付采用至少一次任务处理，目标是效果可对账且不重复占用资源；不宣称分布式 exactly-once。初始版本用一个受信 Worker 进程和有限并发，保留崩溃/重启保护。

## 6 验证与放行

TC-02、TC-03、TC-12、TC-22、TC-24、TC-25、TC-27。重点注入请求迟到、重复领取、租约过期后仍返回成功、外部成功/DB 失败和默认项变化；确认仅一个 Workspace 和正确额度。

已验证真实 PG/Workspace/Terraform/Docker 创建、启停、配置重启、删除保卷及构建响应丢失恢复，恢复只认领匹配后继，不重复提交构建；完整用例状态见 [测试验收](../testing.md)。验证失败时暂停对应能力放行，重新评审方案。

## 7 技术依据

Workspace 稳定名称和 Build 状态转换复用固定 Coder 源码，来源见 [ADR-01](0001-coder-integration.md)。幂等依赖平台数据库唯一约束、持久意图和真实中断/接管测试，不能仅凭类型或查询方法推定。
