# ADR-09 面向对象模块架构与测试驱动开发

- 版本：V0.1
- 范围：单组织Docker初始版本
- 状态：已选择设计，待实现验证
- 负责人职责：前后端开发与测试
- 关联需求：REQ-01～16

## 1 问题

实例、操作、配置、配额和访问存在跨请求不变量。只按HTTP路由组织过程式逻辑容易重复规则，外部失败恢复需要可替换的端口与可观察测试。

## 2 选择

Go使用聚合/值对象封装状态和方法，应用服务组织事务，小接口隔离SQL、Workspace/Terraform、存储、模型和认证；使用组合及构造注入。React 保持函数组件，由类型化客户端和命令/访问用例封装传输与提交恢复。具体见 [对象详细设计](../design.md#8-面向对象详细设计)。

全部新增行为和缺陷修复遵循Red→Green→Refactor。先写领域/用例结果测试，数据库并发与外部认证随模块写真实边界测试；工具和命令见 [TDD设计](../testing.md#6-测试驱动开发)。

## 3 备选与代价

通用CRUD/继承框架会隐藏状态与事务，不采用。把全部React组件改class不利于现有生态，不采用。只靠最后E2E补测试反馈过晚，不能满足TDD；只靠Mock又无法证明资源/认证真实行为，两者须按边界组合。

对象与接口需要命名/边界维护；仅在真实外部依赖或复杂规则处引入，避免每个函数都建接口。版本/时间/随机可注入以便确定性测试，不建立通用工作流引擎。

## 4 验证

代码依赖检查确保领域无HTTP/SQL/Redis导入；关键规则有先失败再通过证据。TC-02、TC-03、TC-09、TC-24、TC-25、TC-39、TC-40验证不变量与事务；真实认证/工具/卷仍按对应TC执行。当前未实现，不宣称测试通过。
