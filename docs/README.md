## 2 事实来源与同步

需求与开发依赖归功能需求；状态和跨模块规则归系统设计；数值/单位/合法性归[配置基线](deployment.md#8-配置与业务规则基线)；技术栈/目录归前后端架构；外部协议归[后端运行适配](backend.md#12-运行适配与外部契约)。公开 API 结构以 OpenAPI 为准，语义归接口文档；数据库文件独立放在 `db/`，`schema.sql` 汇总迁移链，已应用迁移不能改写。安全约束归安全设计，测试状态只在测试验收中维护，ADR 记录选择与代价。

需求→系统/对象→数据/API→前端→测试须同一变更同步。精确依赖以 go.mod/go.sum、package-lock、Provider lock 和固定镜像摘要为准；代码路径与接口名称须能在仓库找到。设计目标、已实现能力和实际通过的验收分别表述，不把计划中的抽象、目录或工具列为当前实现。

用户/角色/权限管理已有SQL、OpenAPI、页面及运行代码；TC-51～60完整产品验收仍待执行。

平台模型网关接入及每用户私有模型统一管理归REQ-16～17。平台为配置权威，Go原生模型入口直接调用官方模型API，不依赖第三方模型代理镜像或Python服务；用户无须进入网关管理。对应D8/D9、TC-61～76；已实现和待验边界集中见[测试验收](testing.md)。

## 3 术语与开发入口

全称 DeepSeek Harness Cloud，简称 DSH Cloud；DSH 是运行应用，版本统一 V0.1。后端 Go + Redis + PostgreSQL，采用 Go 组合/小接口和 TDD；前端 React 函数组件与类型化客户端。

正常运行由平台 Go 内嵌 Workspace/TemplateVersion/Build 和受控 Terraform 执行，元数据存储于平台 PostgreSQL，计算资源运行在本机 Docker。业务字段与容器标签统一 Workspace 命名；上游 Provider 协议、来源许可及不可变已应用迁移见 [ADR-01](decisions/0001-coder-integration.md)。

RUNNING 表示计算/DSH 运行，ready 要求五维健康未过期，can_enter 结合当前身份和必要健康计算；模型故障可授权进入诊断。平台组织与 Workspace 组织 UUID 可不同，映射见[系统设计](design.md#91-组织和身份标识)。

启动与验证使用[根 README](../README.md#本地开发)中的实际命令。新增工作从 REQ/UC/TC、对象和失败断言开始；当前剩余恢复切换、正式部署及完整安全/性能工作见[系统检查](design.md#10-变更与开发检查)和[测试验收](testing.md)。本机备份用于演练，不能替代独立故障域验证。

平台登录使用Go内置OIDC Provider，账号/密码散列与协议状态由平台数据库管理；安全、接口、部署与迁移23文档已同步，实际验证结果集中见测试文档。

默认用户资源配置在“平台配置”按权限初始化和修改，包含 CPU、内存、存储、实例上限与数据保留期限；模型提供商账号及默认模型从“模型提供商”管理。无组织模型不阻止初始化配置；实际创建仍须校验本人所选账号。初始化、修改、版本冲突及资源/额度/保留规则见[功能需求](requirements.md#61-默认配置与凭据)。

工作空间存储数据管理新增为REQ-19，覆盖本人资产查看、实际用量、固定数据目录浏览、保留、备份、恢复与永久回收规则，详见[需求规则](requirements.md#612-工作空间存储数据管理req-19)。本机页面提供只读浏览 `/data/workspace` 与 `/data/dsh`、限额文本预览和下载；接口为API-077～082。数据盘挂载由受信Worker执行，独立备份目标和灾备验收后续另做。

工作空间原生能力还包括内置可选插件启停、第三方 DSH 组合包管理和 Agent 预设默认模式保存。使用与持久化规则见[功能需求](requirements.md#613-工作空间插件与-agent-预设req-07)，服务就绪与平台覆盖边界见[后端契约](backend.md#129-插件管理与预设设置)，当前批准版本、升级和排障见[部署运维](deployment.md#工作空间插件与-agent-预设)，复验命令及证据见[专项验收](testing.md#工作空间插件与-agent-预设验收)。这些能力使用 DSH 原生界面与 RPC，不新增平台公开 API。
