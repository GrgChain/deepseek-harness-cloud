# Graphiti 记忆插件

`@harness-cloud/dsh-graphiti-memory@0.2.0` 是本项目维护的 DSH 原生组合包，适配 DSH `0.2.1-alpha.2`、Node.js 24。不是 Graphiti 官方插件，未发布到 npm。

参照 OpenViking，通过 `dsh-skill-filesystem` 提供 `graphiti-memory` 技能，通过 `dsh-mcp-client` 启动 stdio MCP 服务；不直接注册内置工具。DSH 原生插件管理可查看、停用和重新启用，技能与工具随插件启停。

## 使用

在平台添加并验证 Graphiti 记忆连接。创建工作空间时选择此连接，保持“完整会话同步”开启，平台自动安装并启用插件。无需在 DSH 重填服务地址、凭据、图谱分组或模型。

此版本仅支持平台连接，不提供独立 Neo4j 或 Graphiti REST/MCP 直连配置。下载包用于检查内容或在具备平台代理的新 Profile 中通过 DSH 原生插件页安装、升级；手动安装默认停用，必须使用平台提供的回环端点。普通外部地址不能填为插件 `endpoint`。

已有工作空间的 Profile 不会自动覆盖。旧的 Graphiti 平台适配器需要新建工作空间才能切换到此原生插件；仅重启旧空间不会自动迁移。

## 技能与工具

- `graphiti-memory`：指导模型检索历史、使用来源、核实同步状态及处理关系过时、权限和故障。
- `mcp__graphiti__search`：检索已选连接的全部授权记忆，不接受身份、分组、连接或服务地址参数。
- `mcp__graphiti__status`：查看同步开关、保存数、失败数、丢弃数和待同步量，不返回密钥或正文。

参照 OpenViking，原始会话单独保存，包含用户消息、助手可见回复及工具结果，跳过系统、插件注入、思考、附件和子代理。短会话不会逐条写成记忆。累计约 20,000 个估算 token、开始压缩或会话释放时，调用 Graphiti 原生模型提取长期偏好、事实、约定与经验，只有提取结果进入记忆列表和检索。每轮结束及会话检查点保存原文，按稳定消息标识去重，重启时从持久化事件恢复待同步消息。已删除或人工修改的内容不会因重放恢复或覆盖。最多跟踪 100 个会话、每会话 10000 个标识，待同步文本最多 4 MiB，单条最多 240 KiB；超限跳过并增加丢弃计数。

提取结果与平台手动记忆使用同一命名空间，可在记忆管理中检索、删除和导入导出。原始会话不写入 Neo4j、不参与记忆检索或普通记忆导出；已有旧版记忆及手动记录保留。提取与索引回执持久化，失败可重试。同一用户接入同一连接的多个工作空间共享，其他用户和连接隔离。Graphiti 使用接入服务已批准的模型生成图谱，可能产生模型费用。

MCP 子进程仅接收随机路径回环代理地址，外部凭据及分组由平台服务端保管。每次代理请求重新检查绑定及权限；撤销绑定、停用连接或撤销权限后后续请求被拒绝。停用插件不会删除已有记忆。检索失败不阻断普通对话，同步未完成不会报告成功，具体原因通过状态及平台管理核实。

## 开发

先在仓库根目录执行`npm ci --prefix infrastructure/runtime`安装锁定的DSH依赖，再运行：

```bash
cd infrastructure/plugins/graphiti
npm test
npm run check
```

从仓库使用固定 DSH 依赖测试，不运行安装脚本。平台从 `node infrastructure/plugins/pack-graphiti.mjs` 构建离线归档，校验 SHA-256 后随新工作空间安装，无需访问 npm。
