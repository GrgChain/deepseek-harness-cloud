# Mem0 记忆插件

`@harness-cloud/dsh-mem0-memory@0.2.0` 是 Harness Cloud 编写的 DSH 组合包，支持平台记忆连接和独立连接自部署 Mem0 OSS REST 服务。适配并固定测试 DSH `0.2.1-alpha.2`、Node.js 24；不是 Mem0 官方插件，也不支持 `api.mem0.ai` 托管平台 API。

参照 OpenViking，插件使用原生 Bundle、Config、`dsh-skill-filesystem` 技能提供器和 `dsh-mcp-client`。包含 `mem0-memory` 技能，通过独立 MCP 服务提供工具，不直接注册内置工具；自动同步使用会话事件接口。无安装脚本，不修改 DSH。

## 平台记忆连接

创建工作空间，选择 Mem0 记忆连接并开启“完整会话同步”，平台会自动安装、启用此组合包。DSH 插件管理中可查看 `@harness-cloud/dsh-mem0-memory@0.2.0` 和 `mem0-memory-runtime`，也可通过 `mcp__mem0__status` 查看保存、失败、丢弃计数及待同步字节。

此模式使用 `managed: true` 和平台注入的回环代理，无需在 DSH 重填外部凭据。自动召回、用户消息、助手回复和工具结果同步均开启；系统注入、插件召回、思考、附件和子代理内容不采集。

与 OpenViking 一样，原始会话与长期记忆分开保存：

- 每轮结束及会话检查点同步原始消息，由连接适配层持久化到独立会话表，不直接进入记忆索引。
- 待归档内容达到约 20000 token（按 UTF-8 字节估算）、开始压缩或会话释放时，通过所选 Mem0 服务的 `infer: true` 提取长期记忆。
- 只有提取出的事实、偏好和约定进入记忆管理与自动召回；短会话尚未归档时，列表没有新增记忆不代表同步失败。
- 服务需配置可用的推理模型；本机服务使用已批准的模型配置。推理失败会保留原始会话，后续检查点重试，不用会话原文冒充提取结果。

记忆管理统一展示自动生成与手动添加的记忆，自动生成内容不提供编辑，具备`memory:manage`时可在平台确认删除；检索及导出包含两类记忆，不包含原始会话。旧版已保存的会话记录继续保留。提取使用独立临时命名空间，避免修改手动记忆；回执持久化后重试索引无需再次提取。消息按稳定标识去重，启动时从 DSH 持久化事件恢复未确认消息。同一用户接入同一连接的多个工作空间共享提取后的记忆，其他用户和连接隔离。

同步内容上限为每会话 10000 条、16 MiB 原文；插件合计待同步上限 4 MiB，单条上限 240 KiB，超限明确失败或计入丢弃状态，不截断已保存原文。`mcp__mem0__status` 分别报告同步、归档及记忆生成计数。关闭同步可在创建时取消勾选，运行中可停用原生插件。

MCP 服务以 stdio 子进程运行，仅接收随机路径的本机代理地址，不接收外部凭据。技能和工具随插件停用一起移除，重新启用后恢复。工具不接受用户标识或连接切换参数。

已有工作空间的 Profile 不会因平台更新被覆盖；该自动安装流程对更新后新建且开启同步的工作空间生效。

## 独立安装与配置

从插件库下载 `.tgz` 并在 DSH 手动安装时，插件默认停用。配置 `mem0-memory-runtime` 后再启用。下面的独立配置使用 `managed: false`（默认值），不使用平台记忆连接；其采集开关、命名空间和故障处理与上面的平台模式分别生效。

在工作空间的用户配置层 `cordis.patch.yml` 中加入以下配置。DSH Loader 支持 `!!js` 环境引用；不要把实际密钥写入聊天、Git 或公开配置。

```yaml
- id: mem0-memory-runtime
  disabled: false
  config:
    endpoint: http://mem0:8580
    apiKey: !!js process.env.MEM0_API_KEY
    userId: !!js process.env.MEM0_USER_ID
    autoRecall: true
    autoCapture: false
    captureAssistant: false
    infer: false
    topK: 5
```

`endpoint`、`apiKey`、`userId` 必填。地址必须能从 DSH 容器访问；宿主机的 `localhost` 不是工作空间。项目本机服务使用 `http://mem0:8580`，工作空间还需接入可访问它的网络；宿主机调试地址 `http://127.0.0.1:18583` 仅供宿主机调用。不要将平台内部签名接口 `18580/mem0` 填到此处。自建远程服务应使用 HTTPS。

`userId` 是此独立插件固定使用的 Mem0 命名空间。检索和写入始终携带它，工具不能改写；只向同一位用户的受信任工作空间配置同一 ID 和凭据。此命名空间**不会自动与平台记忆连接中的命名空间共享**，插件直写的记忆也不会自动出现在平台的连接管理列表。凭据能访问哪些数据最终由服务端决定，切勿向不同用户分发同一管理员密钥。插件不持久化密钥或会话队列。

| 配置               | 默认值   | 说明                                                       |
| ------------------ | -------- | ---------------------------------------------------------- |
| `autoRecall`       | `true`   | 在新的用户轮次检索一次并注入相关记忆                       |
| `autoCapture`      | `false`  | 用户显式开启后，自动发送人类输入的可见文本                 |
| `captureAssistant` | `false`  | 开启自动采集后，可额外保存助手可见回复；不含思考或工具调用 |
| `infer`            | `false`  | 原文直存；开启后服务端可能调用其配置的模型并产生费用       |
| `topK`             | `5`      | 检索条数，1–20                                             |
| `timeoutMs`        | `10000`  | 每次请求超时，100–60000 毫秒                               |
| `maxContentChars`  | `12000`  | 单次写入和单条返回记忆长度上限，100–262144                 |
| `maxQueryChars`    | `4000`   | 检索问题长度上限，1–4000                                   |
| `maxContextChars`  | `6000`   | 自动召回上下文总长度上限，100–32000                        |
| `maxResponseBytes` | `262144` | HTTP 响应上限，1024–1048576 字节                           |

本地 REST 服务默认使用 `infer: false`；只有明确设置 `infer: true` 时才使用已配置的推理模型。自动采集默认关闭；启用意味着之后的用户文本会发送到所配置 Mem0 服务，开启 `captureAssistant` 还会发送助手回复。它不只识别“请记住”语句。关闭或卸载插件不会删除已保存的数据。

## 能力与边界

下面的自动采集、去重、队列与非幂等写入限制描述独立模式；平台模式的会话恢复与归档重试见[平台记忆连接](#平台记忆连接)。

- `mcp__mem0__search`：按问题检索固定用户、`personal` scope 的记忆，可指定 1–20 条；不返回密钥。
- `mcp__mem0__remember`：仅独立模式提供。保存用户明确要求记住的文本，经 DSH 原生工具执行审批展示完整内容、目标服务和用户标识，并要求单次人工确认。没有确认服务、拒绝或取消时不写入。
- `mcp__mem0__status`：只读查看开关、待保存数、成功/失败/丢弃数和通用错误；不含密钥、记忆正文或服务端原始错误。
- 自动召回只读取当轮 `source.kind=user` 的输入，每轮至多一次；只注入带来源标记的不可信参考内容，保留 DSH 的原始决策字段。
- 自动采集读取后续提交的 `session/event`，不扫描或重新保存旧 `session.events`。只采集人类输入；助手回复需额外开启。系统、工具、其他插件的注入、附件、思考和子代理会话均不采集。
- 在 `turn/end` 和 `session/flush` 保存排队文本，每条折叠为一条 Mem0 用户消息，附带会话/消息来源元数据。使用稳定消息 ID 去重，同一进程中同一条消息不会重复发送。
- 存储服务断开或返回错误时，不阻断普通自动召回；自动写入失败写入状态并记录不含正文的通用警告。手动保存明确返回失败，HTTP 成功但缺少回执也不报告保存成功。
- 不自动重试非幂等写入。超时可能已在远端完成，请先检查服务再重新保存。队列只在内存中，进程崩溃或停用插件时未发送内容可能丢失；停用会取消在途请求，不保证跨重启恰好写入一次。
- 为控制内存，最多跟踪 100 个主会话，每个会话跟踪 2000 个消息 ID，全部会话合计最多缓冲 100 条、1 MiB 文本（含在途请求）；超限或单条超长时跳过，并在状态中增加 `dropped`，不会悄悄截断保存正文。

## 本地开发与打包

先在仓库根目录执行`npm ci --prefix infrastructure/runtime`安装锁定的DSH依赖。下列测试及打包命令本身不下载第三方包：

```bash
cd infrastructure/plugins/mem0
npm test
npm run check
npm pack --ignore-scripts
```

测试使用原生 DSH `Config`、`createUserMessage`、本机 HTTP fixture 和真实 stdio MCP 子进程，覆盖会话过滤、每轮去重、审批入口、固定身份、取消、超时、限额、错误与不重试。真实 DSH 另验证技能和 MCP 工具的加载、启停和重启，真实 Mem0 SDK 和 Qdrant 的验证由本仓库本地集成环境执行。

在平台插件库离线添加生成的 `.tgz` 包即可保存并下载该原包。添加到插件库与在 DSH 安装/启用是不同步骤；此包没有发布到公共 npm。
